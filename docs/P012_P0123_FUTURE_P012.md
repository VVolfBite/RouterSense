# P012, P0123 advisory, and Future-P012

RouterSense exposes three distinct modes without changing the execution traffic contract.

| Mode | Planning horizon | Planning timing | Executed traffic |
|---|---|---|---|
| `routersense_p012_async` | current P0/P1 + predicted P2 | target layer/on demand | current P0/P1 only |
| `routersense_p0123_async` | current P0/P1 + predicted P2 + derived `P3=P2^T` | target layer/on demand | current P0/P1 only |
| `routersense_future_p012_async` | target P0/P1 + predicted target P2 | previous layer | target P0/P1 only |

P0123 is an advisory-horizon ablation. It does not materialize or execute predicted P2/P3 bytes.

Future-P012 reuses the exact P012 planner. The source layer predicts the target dispatch and the following dispatch, builds an immutable target plan, and publishes it through `TargetPlanStore`. At the target layer, actual P0/P1 traffic is reconciled with that prepared plan. The target layer does not invoke a second full planner unless the existing bounded repair path is required.

The required runtime evidence is:

- `planning_horizon`
- `planning_timing`
- `execution_scope`
- planner build time
- prepared-plan ready time
- target frontier time and ready margin
- bind/reconciliation time
- repair status and preserved-order ratio

The original P012 mode remains the compatibility and paper baseline. Future-P012 must produce the same plan as on-demand P012 for identical predicted matrices, topology, policy, and weights.
